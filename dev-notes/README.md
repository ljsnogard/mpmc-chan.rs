# dev-notes

本目录记录 `mpmc-chan` 的设计推演、并发路径、技术决策与实施记录。

## 文件命名

- 文件名格式：`[模块名]-YYYYMMDD-hhmm.md`，例如 `mpmc-design-20261025-1535.md`。
- 同一主题的后续讨论优先追加到同一文件；发生方向性改变时新建文件，并在旧文件顶部标注「已废弃」与替代文件。
- 日期使用本地时间（Asia/Shanghai）。

## 写作要求

- **先给结论**：文件开头用一小段说明当前结论与状态（讨论中 / 已裁决 / 已实施）。
- **以因果链为主**：写清楚「为什么这样决策」，而不只是「做了什么」。
- **并发方案必须可审计**：至少列出快路径、慢路径、竞争失败、取消、关闭、析构六类路径，并写明每条路径上的锁状态、唤醒责任与存活论证。
- **证据优先于推断**：涉及运行时行为、编译器能力、性能数字的结论，附可复现的命令与原始结果；未实测的内容明确标注为推断。
- **及时清理过时内容**：技术决策改变后，与最终决策无关的旧讨论应删除或标注「已废弃」。
